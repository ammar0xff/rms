# Full-system audit — 2026-10-15

Five parallel subsystem audits (sync, update flow, repositories, bootstrap/auth,
UI state) returned ~40 findings. Every fix below was verified against the code
first; several agent claims were downgraded or rejected on verification.

## Fixed

### Update flow (safety-gate grade)
- **Coordinator never awaited the download.** It read only `start()`'s return
  value (`starting`) and never the terminal progress state, so every production
  download failed at verification. Same signature as the field report of
  فشل التحقق. Now settles on the terminal state, failing closed otherwise.
- **TOCTOU on AC-35.** `apply()` trusted the check-time readiness verdict while
  holding a fresh work snapshot it never consulted. It re-classifies at apply
  time now.
- **Null outbox read as empty backlog.** Unknown work withholds the install via
  an explicit `unknownWork` flag. (Production never hits this — the runtime
  only exists alongside a store — but unknown must never read as empty.)
- **Checksum-less manifests installed.** Despite the docstring, the manifest
  contract, and fail-closed all saying reject. Only verified checksums satisfy
  the gate now.
- **Failed attempts were a dead end.** Enforced screen, disabled button, no
  exit wired (`acknowledge()` existed, nothing called it). Failed is
  dismissible with لاحقًا and a retry that re-checks then applies; completed
  dismisses too. Deferring an optional prompt no longer suppresses
  mandatory/in-flight/failed screens.
- **Gate refusals left no audit trail.** The most safety-relevant decision now
  emits `updateWithheld`.
- Refresh compared build numbers alone (pinned devices, could lose newer
  cached docs); now joint with semantic version. Backend bounds no longer
  brick the fleet when no backend version is reported. Health passes
  older-than-binary migration targets.
- Removed the write-only `UpdateDeps.outbox` field.

### Sync
- Fold-back failure resurrected synced entries (re-push, double order numbers,
  duplicate audit rows). Transport and fold-back failures handled separately;
  the latter parks as `requiresUserAction`.
- Exhausted budgets stranded entries silently (and held the update gate shut).
  They park visibly now.
- Backoff was dead code (`nextDelay` had no callers). Honored against
  `lastAttemptAt`; made robust to zero-delay policies.
- Failed counter reservations synced numberless orders permanently. The push
  throws instead; replays reuse the reservation written back into the doc.
- Offline drains burned attempt budget. `requestSync` refuses while offline.
- Bluetooth/`other` counted as online. Only wifi/mobile/ethernet/vpn qualify.
- Tapping the sync chip falsified the online flag feeding real decisions.
  Display-only now. Outbox writes are single transactions. Parked entries count
  in the monitor instead of vanishing.

### Money and data
- **POS charged tax the order never contained.** Payment incl-tax vs
  order/delivery/receipt ex-tax on every taxed order. Tax (cents-rounded) is
  stored on the order; all four read one total.
- Double-tap created two orders (no re-entrancy guard). Tab switches wiped the
  cart (no keep-alive). Tab controller reset on every setState. All fixed:
  guard, hoisted controller, offstage body cache in the shell.
- `finalizeSettlement` checked idempotency outside its transaction (double
  settle, two server docs). Inside now.
- Collection receipts dirtied deliveries with no delivery command; purchase
  receipts bumped payables no command could attribute. Acks clear flags when
  quiet; receive payloads carry supplier id + resulting payable.
- Migration runner reported success short of target. Backward ticket/delivery
  transitions rejected at the data layer.
- Collect celebrated unwritten money (null return ignored). Station filter
  orphaned itself. AuthGate flashed sign-in for persisted sessions. Startup
  crashed on configured builds (eager Firestore instance). Version validation,
  online-flag consistency, auth code coverage as listed in commits.

## Deliberately not fixed (with reasons)
- `minSupportedVersion` gate direction — needs the PRD addendum's ruling.
- `applySynced` stamping over newer local edits — needs a revision-carrying
  design, not a one-line guard.
- `cache*({replace:true})` vs pending rows — needs a merge/refuse policy.
- Nullable audit log — needs constructor changes across repos + tests.
- Purchase line items in sync payloads — server contract decision.
- Money as double — minor-units migration, large.
- Kitchen tickets have no outbox entries — needs a ruling on whether tickets
  are supposed to sync at all.
- Branch-switch staleness, mock-data screens, settings ack loop — need
  navigation/remount and down-sync design decisions.
- Release logging in prod builds, `signOut` wiring, rollback executor,
  `dependencyIds`, `serverReceivedAt` dead weight — backlog, ordered by risk
  in the checklist.
- Demo seeds in prod first-run — kept: there is no down-sync path, so the
  seeds double as the initial catalog. Removing them strands fresh installs.
- `app_bootstrap.dart` unit tests — refused on principle (see Phase 5 notes).
